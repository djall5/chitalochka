# Совместные уроки в реальном времени

Сайт использует Supabase Realtime для комнат уроков, статуса участников, курсоров и синхронизации шага/баллов. Пока переменные Supabase не заданы, обычные уроки продолжают работать, а панель покажет инструкцию.

## Облачное сохранение между устройствами

Уроки, карточки учеников и результаты сохраняются в локальном хранилище браузера. Чтобы переносить их между устройствами, добавлено сохранение в личное облачное пространство Supabase. У каждого аккаунта отдельная строка, защищённая политиками RLS.

1. В Supabase откройте **SQL Editor** и выполните SQL из `supabase/schema.sql`.
2. В настройках проекта откройте **Authentication → Providers → Email** и оставьте включённым вход по email и паролю. При необходимости включите подтверждение почты.
3. В GitHub откройте **Settings → Secrets and variables → Actions → Variables** и создайте переменные `VITE_SUPABASE_URL` и `VITE_SUPABASE_PUBLISHABLE_KEY`. Значения возьмите из настроек Supabase: Project URL и publishable key. Эти значения предназначены для клиентского приложения; `secret` и `service_role` ключи сюда добавлять нельзя.
4. После следующей успешной сборки откройте сайт, создайте аккаунт и войдите. Данные, которые уже сохранены в этом браузере, загрузятся в аккаунт при первом входе. На другом устройстве войдите с тем же аккаунтом.

Если данные уже есть в облаке, при входе на другом устройстве они заменят локальные данные этого браузера. Изменения сохраняются автоматически с небольшой задержкой.

## Кабинет ученика

Для доступа ученика по персональной ссылке после `schema.sql` выполните `supabase/student-portal.sql` в SQL Editor. Учитель открывает карточку ученика и нажимает **Создать ссылку**. По ссылке ученик увидит уроки и результаты только своей карточки. Завершённые занятия сохраняются в эту карточку. Ссылка является секретом доступа: передавайте её только нужному ученику; создание новой ссылки отключает предыдущую.

## Подключение Supabase

1. Создайте проект в Supabase.
2. В Project Settings / Connect скопируйте Project URL и **publishable key** (`sb_publishable_...`). Ключ `secret` или `service_role` в сайт добавлять нельзя.
3. В корне проекта создайте `.env.local` на основе `.env.example` и вставьте значения:

   ```env
   VITE_SUPABASE_URL=https://ваш-проект.supabase.co
   VITE_SUPABASE_PUBLISHABLE_KEY=sb_publishable_ваш-ключ
   ```

4. Перезапустите dev-сервер. Для проверки на другом устройстве сайт должен быть опубликован по адресу, доступному этому устройству; `127.0.0.1` открывает сайт только на текущем компьютере.
5. Откройте урок, нажмите «Подключить ученика» → «Создать комнату». Передайте ученику ссылку или код. Ссылка подключает его как ученика; код можно ввести вручную.

Для стартового прототипа сессия работает через публичный Realtime-канал с длинным случайным кодом-комнатой. Участник, которому известна ссылка/код, может войти. Перед использованием с реальными учениками добавьте аутентификацию или серверную выдачу одноразового доступа и правила приватных каналов. Не передавайте через комнату личные данные детей. Сообщения комнаты временные и не записываются в таблицы базы данных.

Курсоры передаются через Broadcast с ограничением частоты, а присутствие участников отслеживается через Presence. Presence предназначен для статуса подключения, не для отправки каждого движения мыши: https://supabase.com/docs/guides/realtime/presence
